# 功能 5 — 首次运行、现有文件扫描与暂停语义

## 该功能要解决的用户问题

两类事故要在产品层挡住：

1. 第一次打开就把几年来的 Downloads 全部搬走（用户还没看默认规则）。
2. 正在下大型 ISO / 正在连拍截图时，需要一键暂停而不是退程序。

## 范围 / 非范围

**范围**

- 无配置时的首次对话框。
- `first_run_at` 初始化。
- 手动「整理现有文件」确认框。
- 暂停 = 只跳过 execute。
- 归档根目录选择（首次 + 托盘菜单同一套）。
- OneDrive 落点警告；开机启动知情同意一句。
- 首次不搬旧文件、归档根默认 `Documents\Weekcase`：用户已确认 2026-08-30（OQ-1 / OQ-3）。

**非范围**

- 完整设置 GUI（规则编辑、预览匹配列表）。
- 向导式多页 onboarding。

## 行为规格

### 首次运行

条件：`config.toml` 不存在。

对话框（Win32，中文）：

```
Weekcase 将监视：
  下载：<resolved>
  截图：<resolved 或「尚未创建，出现后自动监视」>
归档到：
  [路径只读框] [浏览…]
默认不会移动已经在文件夹里的旧文件。
下载会在原文件夹里大约留 7 天再归档（刚下的还能打开）。
截图大约几十秒后归档。
之后可以从托盘选择「整理现有文件」来立刻收旧文件。
本程序会随 Windows 登录启动（可在托盘关掉）。
[若 root 或任一源位于 OneDrive 已知路径下：]
  警告：该路径由 OneDrive 同步。归档会上传到云端。建议改到本地磁盘。
        [开始]   [退出]
```

开始：写默认配置（含用户选的 root）、写 `state.json`（`first_run_at`）、启动 watch。退出：不写配置，进程结束。

解析 root 后检测：`SHGetKnownFolderPath(FOLDERID_OneDrive)` 是否为其前缀，或规范化路径含 `\OneDrive\`。不因此改默认 `Documents\Weekcase` 算法，但警告必须出现。

### 现有文件

- 默认启动列举按入候选资格表规则 1/2，**不用** `process_start`，**不用** watermark。
- 菜单「整理现有文件」→ `MessageBox`：「将按当前规则移动两个源目录顶层的已有文件（含未满 7 天的下载），可随后撤销。继续？」Yes 才发功能 1 那个 `WatchCmd::Rescan { include_existing: true, min_age_override: Some(0) }`。
- 一次 Rescan **不保证** 收完超过 256 个文件。若 `overflow_unacked`：托盘保持失败态「有文件没进队，整理未完成」；用户再点同一项继续。自动周期列举不会收 `created < first_run_at` 的剩余存量。

### 暂停

| | T1 Watch | 候选表 | T2 稳定字段 | T2 Move |
|--|----------|--------|-------------|---------|
| 运行 | 开 | 更新 | 更新 | 执行 |
| 暂停 | 开 | 更新，**不丢弃** | 更新 | **跳过** |

暂停期间：已到龄的可 upsert 进表但不 Move；**未到龄的下载不进表**。恢复 = 清原子，表中 ready 项下一 tick 执行；年轻文件等下一轮周期列举到龄后再进表。256 上限只约束已到龄项。

### 失败

用户选的归档根无法创建：对话框报错，不开始。
用户选的根在源内部、盘符根、Profile、Windows、Program Files*、ProgramData、UNC、`DRIVE_REMOTE`：拒绝。

## 与总体架构的接口

无第二份 `WatchCmd`。暂停：`Arc<AtomicBool>`（可与 `config.general.paused` 同步落盘）。

## 关键实现要点

对话框用 `DialogBoxParamW` 资源或直接 `CreateWindow` 几个控件。允许临时用 `MessageBox` + `IFileDialog` 拼出 MVP，但「选择归档文件夹」与首次选 root 必须走同一校验函数。

## 验收标准

1. 干净用户，Downloads 里预放 100 个旧 PDF，首次「开始」后 5 分钟它们仍在 Downloads。
2. 选「整理现有文件」并确认后，这 100 个在 settle 后进入 `{root}/Downloads/Documents`。
3. 暂停时新截图稳定后不移动且仍在候选表；恢复后下一秒内进入落点（不必等 60 s）。
4. 首次选根为 Downloads 子文件夹：拒绝开始。
5. 干净用户，Downloads 有旧文件，进程退出后再放入一个新文件并启动：只搬走新文件。
6. Downloads 预放 **300** 个旧 PDF，点一次「整理现有文件」：进队 ≤256，托盘「整理未完成」；再点一次后其余进入候选/搬走，无一批永远留在源。
7. 启动后新放入一个 PDF：默认配置下 **7 天内不搬走**（测试可注入短 min_age 验证同一分支）。

## 本功能开放问题

无。首次不扫旧文件已拍板（OQ-1，2026-08-30）。
